# 2026-11-09 HA 客户 C 开发与验证范围

本记录是脱敏的既有实测摘要，不包含设备地址、域名、人员、密钥、令牌、备份文件名或现场日志。此次发布不会重新操作生产设备；发布副本中的地址替换和文档整理不宣称再次现场部署。

## 已有实测

| 项目 | 实测范围 |
|---|---|

| 独立身份 | 节点 WG、受限协调 SSH 与 Agent 主机身份独立；迁移后关键身份及许可令牌摘要一致 |
| WG 管理 | 新握手，维护电脑访问 HA HTTP 200；宿主 root SSH 实际公钥登录，主机身份与物理 LAN 入口一致 |
| Agent | 服务端专用身份可 probe；任意 hostname 命令被拒绝，只有限定方法；本地 API 拒绝未认证请求 |
| 控制生命周期 | C OFF、DISCONNECT、RECONNECT 成功；重连后 OFF；同家庭网段 ON 正确拒绝 |
| A/B 与个人 WG | A/B 原本均 OFF，保持 OFF；Peer 配置、个人 WG Peer 摘要一致；未为 C 实测切换既有业务 |
| 活跃其他客户保护 | Lua 5.1 模拟执行中，另一客户持有业务时 C ON 被拒绝，C OFF 不清空其他客户租约；未在生产开启 A/B 来验证该分支 |
| 本地许可 | HA 关闭许可后管理 HTTP 200；重新打开仅恢复许可，业务仍 OFF；迁移加载项后再次验证 |
| 内核执行器 | `--network none` 独立容器中完成 nft 安装、ON、续租、OFF、专用路由及 Docker 转发规则回滚 |

| 停止与启动 | 修正 PID 1 信号转发后，真实节点 stop/start 约 3 秒、退出码 0，WG 接口正常清理，管理重新恢复 |
| Supervisor 迁移 | 本地加载项安装、启动、重启成功；保护模式开启、只加 NET_ADMIN、无 full_access 或 Docker API；boot=auto |
| 支持状态 | 原生健康检查返回 unsupported=[]、unhealthy=[]、supported=true、healthy=true；HA 修复列表为空。未忽略提示或关闭检测 |
| LuCI | 新增 C list/control RPC 成功；名称/备注、状态、网段、拒绝原因、本地许可和 HA 管理入口已接入；视觉浏览器验收未完成 |
| 备份 | 完整 HA 备份下载后独立读取、SHA256 匹配；检查加载项归档确实包含关键私有状态，未输出内容；不是全盘镜像 |

## 明确未验收

- 独立客户 LAN 的正向 ON、真实终端访问、SNAT 端到端回包。
- 真实客户终端、HA 与桥接容器的完整反向攻击面、存活 TCP/UDP 会话撤权。
- 现场网关/KNX/ETS、广播组播发现、额外 VLAN。
- 加载项迁移后的整机冷启动、WAN 断线和公网 Endpoint 地址变化恢复。
- 所有客户的正向互斥切换；已有路由器节点仍有全局单业务语义。
- 备份真实恢复演练及冬瓜全部系统修复工具的兼容性。

## 两次故障的结论

独立容器曾收到停止请求，在 10 秒内未退出而被强制终止；不是内存不足，之前健康检查正常。`unless-stopped` 不会在系统启动后恢复此前主动停止的容器。未查明具体哪一个第三方系统修复按钮发起了停止，不能将相关性当作证据。

后续系统运行时钩子还出现缺少元数据字段导致的 ifthen(null) 错误。临时独立容器补充了真实 standalone 类型与版本，没有改全局钩子或伪装成加载项。最终迁移为真实 Supervisor 本地加载项，解决独立软件支持状态问题。旧实例停止并关闭自启，原状态、镜像和检查点保留。

本发布包含 31 项新增模型/Agent/控制器/信号测试，以及原项目回归测试。离线测试、模板语法检查、内核隔离试验和现场管理验证是不同层级的证据。
