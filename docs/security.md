# 安全模型和已知限制

## 不进入仓库的内容

真实域名/公网地址、客户清单、现场私有网段、设备身份、运行日志、抓包、设备配置备份、WG 私钥/PSK、SSH 凭据、Wi-Fi 密码、authorized_keys/known_hosts 和真实生成包。Private 仓库仍需遵守这一约束。

使用白名单提取、示例模板、仓库外渲染、逐文件审查和本地 gitleaks。扫描器只在本机执行，不把源码发送给外部审计服务。`.gitignore` 不是保密边界，推送前还要审核暂存内容、文件树、历史、远端 owner 和 PRIVATE 状态。

## 权限边界

- `knx-customer` 是唯一业务控制入口。RPC 无任意命令执行，客户 ID 和四种修改操作均严格校验；命令使用固定程序 + argv，不拼 shell。
- rpcd ACL 分离 list/status 读权限与 control/update_metadata 写权限，依赖现有有效 LuCI 会话和 CSRF/session 机制；不新增匿名 API。
- UI 禁用重复点击；RPC 请求 ID 幂等记录、修改锁以及控制器全局锁减少并发冲突。名称/备注验证 UTF-8、长度、控制字符、乐观版本号，使用文本节点显示，不信任 HTML。
- 近期握手不是在线保证；返回码和实际状态不一致时显示失败。原因过滤敏感文本；管理页面仍不应记录密钥或密码。
- 专用 SSH forced-command 密钥只能调用 Agent 的有限动作；Agent 再校验 WG 管理源和候选指纹，主机密钥必须固定。设备使用 root 执行受限 Agent，root/私钥失陷不在此控制器可防御的威胁范围内。

## 数据面边界

ON 授权私有维护 LAN，而不是客户上游设备主动访问家庭；真实 WAN→家庭只允许授权连接的返回。私有源还绑定 br-lan 入口，WG 源归属依赖相应 Peer AllowedIPs。全局只激活一家客户真实 LAN，不提供家庭互联网默认出口。

OFF 先清 nft 租约和授权集合，再撤销所属策略/路由/业务 AllowedIPs，并定向删除两方向业务 conntrack；不清全局连接表，不删除管理 Peer。内核短租约可以在用户态监控失效后关闭业务，但不构成无限制 root 恶意软件防护。

已知客户前缀保存在设备内的 known 集合；动态识别到新客户前缀之前，不可能凭空辨认某个普通互联网目标属于未来客户。OFF 撤销的是本系统已知和已授权的业务路径，不承诺为任何未知网络建立全局互联网黑洞。

## 部署限制与待验证风险

1. V1.0 的客户注册可扩展，但若干管理 guard、gate 文件和服务调用仍为单客户槽位；**不能直接拿它当成已验收的任意多客户产品**。新增客户需独立源前缀、管理规则和实际互斥/隔离测试。
2. IPv6 WG 业务转发拒绝；没有 IPv6 业务、广播桥接、组播发现或虚拟 DNAT。厂商协议携带内部地址时可能需要客户端 NAT 模式或专门适配。
3. 特殊公网地址拒绝列表是静态实现，需定期审阅；DoH 提供商会看到 Endpoint 查询，不代表端点 DNS 权威数据由本程序更新。证书校验和正确系统时间必需。
4. 不保证所有 OpenClash 版本、提前链、flowtable/硬件卸载组合都等价；需审阅 hook 顺序并实测 OFF 撤权。不能通过放宽转发或关闭保护来解决兼容问题。
5. 表号/优先级、dbclient 参数、fw4 链名、Lua 兼容模块、接口名、GID 绕行契约、netifd nohostroute 支持均为平台适配要求。模板生成成功不等于可以安全安装。
6. 两次健康探测和恢复防抖不是无缝切换保证；冷启动、上游黑洞、WAN 换网段、服务异常和多客户竞争未完成全覆盖现场故障注入。
7. Peer 恢复不支持未经补充实现的 PSK 场景。控制器监控列表当前串行查询，新增很多客户还需评估超时与租约调度，不得仅扩大列表。
8. 本地 UI 后端的状态执行沿用 V1.0 实现；没有宣称已进行完整渗透测试。保存元数据不会触发 VPN 修改，但真实备注可能含隐私，不应同步进源码库。

## 发现泄漏时

停止推送，先撤销/轮换暴露的凭据，再评估 Git 历史、远端复制和授权访问；删掉工作区文件或设为 Private 不能撤回已泄漏凭据。通过私有维护渠道报告问题，不在公开 Issue 粘贴客户资料或配置。

本项目没有添加未经确认的开源许可证，也未把设备备份作为源码授权内容。
